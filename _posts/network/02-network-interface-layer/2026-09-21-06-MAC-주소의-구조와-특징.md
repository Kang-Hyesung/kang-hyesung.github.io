같은 로컬 네트워크에 여러 장치가 연결되어 있다면 Ethernet 프레임을 어느 인터페이스가 받아야 하는지 구분할 주소가 필요하다. 이때 데이터 링크 계층에서 사용하는 주소가 **MAC 주소(Media Access Control Address)**다.

스위치는 수신한 프레임의 출발지 MAC 주소를 학습하고 목적지 MAC 주소를 조회해 전달할 포트를 결정한다. MAC 주소의 구조를 이해하면 하나의 PC에 주소가 여러 개 보이는 이유, 가상 머신이 별도 주소를 사용하는 이유와 라우터를 지날 때 주소가 바뀌는 이유를 함께 설명할 수 있다.

## MAC 주소는 장치보다 인터페이스에 가깝다

MAC 주소를 PC 한 대에 하나씩 부여되는 주소라고 생각하기 쉽지만, 정확히는 **네트워크 인터페이스에 사용하는 주소**다. 따라서 하나의 장치가 여러 MAC 주소를 가질 수 있다.

- Ethernet NIC와 Wi-Fi NIC가 모두 있으면 각 인터페이스가 별도의 MAC 주소를 사용한다.
- 가상 머신의 가상 NIC에도 MAC 주소가 할당된다.
- 컨테이너와 가상 네트워크 인터페이스도 구성 방식에 따라 별도의 MAC 주소를 사용할 수 있다.
- 하나의 스위치 상향 포트에서는 그 너머에 있는 여러 인터페이스의 MAC 주소가 학습될 수 있다.

NIC(Network Interface Card)는 장치를 네트워크에 연결하는 하드웨어 또는 논리 인터페이스다. 현대 장비에서는 메인보드 내장 Ethernet, USB 어댑터, 무선 인터페이스처럼 형태가 다양하므로 반드시 별도의 카드 모양일 필요는 없다.

## 48비트 주소의 표현

일반적인 Ethernet MAC 주소는 48비트, 즉 6바이트다. 각 바이트를 두 자리 16진수로 나타내므로 다음과 같은 형식으로 볼 수 있다.

```text
00:1A:2B:3C:4D:5E
00-1A-2B-3C-4D-5E
001A.2B3C.4D5E
```

표현 방식은 달라도 세 값은 모두 같은 48비트 주소를 나타낼 수 있다. 운영체제와 네트워크 장비 종류에 따라 콜론, 하이픈 또는 네 자리씩 묶는 점 표기를 사용한다.

## OUI와 인터페이스 식별 부분

전통적으로 많이 사용하는 IEEE **MA-L 주소 블록**을 기준으로 보면 MAC 주소를 다음과 같이 나눌 수 있다.

```mermaid
flowchart LR
  oui["상위 24비트<br/>OUI"] --- extension["하위 24비트<br/>확장 식별자"]

  classDef organization fill:#164e63,stroke:#22d3ee,stroke-width:2px,color:#f8fafc
  classDef interfaceId fill:#713f12,stroke:#facc15,stroke-width:2px,color:#f8fafc

  class oui organization
  class extension interfaceId
```

- **OUI(Organizationally Unique Identifier)**: IEEE가 등록 조직이나 제조사에 할당한 상위 24비트다.
- **확장 식별자**: 해당 조직이 자신에게 할당된 범위에서 인터페이스를 구분하는 하위 24비트다.

예를 들어 `00:1A:2B:3C:4D:5E`에서는 `00:1A:2B`가 OUI, `3C:4D:5E`가 확장 식별자에 해당한다. IEEE에는 MA-L 이외에 다른 크기의 주소 블록도 있으므로 모든 MAC 주소를 언제나 제조사 24비트와 제품 일련번호 24비트로만 해석할 수 있는 것은 아니다.

> 하위 24비트를 `UAA`라고 부르는 설명이 있지만 엄밀히는 다르다. **UAA(Universally Administered Address)**는 U/L 비트가 전역 할당을 나타내는 MAC 주소 전체를 뜻하며, 하위 24비트만의 이름이 아니다. MA-L 구조의 하위 24비트는 확장 식별자로 이해하는 편이 정확하다.

## I/G 비트와 U/L 비트

MAC 주소 첫 바이트에는 주소의 성격을 나타내는 비트가 포함된다.

| 구분 비트 | 값 | 의미 |
| :--- | :--- | :--- |
| I/G | `0` | 개별 인터페이스를 나타내는 유니캐스트 주소 |
| I/G | `1` | 여러 인터페이스를 대상으로 하는 그룹 주소 |
| U/L | `0` | IEEE 할당 체계를 따르는 전역 관리 주소 |
| U/L | `1` | 관리자가 정하거나 소프트웨어가 생성한 로컬 관리 주소 |

I/G 비트는 프레임이 개별 인터페이스를 향하는지 또는 멀티캐스트·브로드캐스트 같은 그룹을 향하는지 구분한다. U/L 비트는 IEEE 할당 체계를 따르는 주소인지 로컬에서 관리하는 주소인지 구분한다.

## MAC 주소가 항상 고정되고 유일한 것은 아니다

MAC 주소를 물리 주소나 하드웨어 주소라고도 부르지만, 반드시 하드웨어에 영구적으로 고정되거나 현실의 모든 네트워크에서 유일하다고 가정할 수는 없다. 운영체제에서 주소를 변경할 수 있고, 가상 머신과 컨테이너가 소프트웨어로 주소를 생성하며, Wi-Fi 단말은 추적을 줄이기 위해 임의 주소를 사용하기도 한다.

중복된 MAC 주소가 같은 링크에 나타나면 스위치의 MAC 주소 테이블 항목이 포트 사이를 오가거나 프레임이 엉뚱한 포트로 전달되어 통신이 불안정해질 수 있다. 가상 환경에서 MAC 주소 범위를 관리하는 이유도 같은 링크 안의 중복을 피하기 위해서다.

## MAC 주소는 로컬 링크에서 사용한다

MAC 주소는 일반적으로 현재 로컬 링크에서 프레임을 전달하는 데 사용한다. 패킷이 라우터를 통과해 다음 네트워크로 이동하면 라우터는 해당 링크에 맞는 새 프레임을 만들므로 출발지와 목적지 MAC 주소가 바뀐다.

반면 출발지와 목적지 IP 주소는 NAT 같은 변환이 없다면 종단 간 경로에서 유지된다. IP 주소가 여러 네트워크를 지나 최종 목적지를 식별한다면, MAC 주소는 현재 링크에서 다음 장치로 프레임을 전달하는 데 사용한다고 구분할 수 있다.

## Windows에서 MAC 주소 확인하기

PowerShell에서는 네트워크 어댑터별 MAC 주소와 연결 상태를 확인할 수 있다.

```powershell
Get-NetAdapter | Format-Table Name, Status, MacAddress, LinkSpeed
```

명령 프롬프트에서는 다음 명령을 사용할 수 있다.

```powershell
getmac /v
```

IPv4 주소와 MAC 주소의 대응 관계를 확인하려면 ARP 캐시를 조회한다.

```powershell
arp -a
```

`arp -a`는 현재 PC가 알고 있는 IP·MAC 주소 대응 관계를 보여주며, 스위치 내부의 MAC 주소 테이블을 보여주는 명령은 아니다. 관리형 스위치의 MAC 주소 테이블은 해당 장비의 관리 인터페이스나 명령줄에서 별도로 확인해야 한다.

## 정리

- MAC 주소는 같은 링크에서 네트워크 인터페이스를 식별하는 데 사용한다.
- 일반적인 Ethernet MAC 주소는 48비트이며 6개의 16진수 바이트로 표현한다.
- MA-L 주소는 OUI와 하위 확장 식별자로 나누어 이해할 수 있다.
- UAA는 하위 24비트의 명칭이 아니라 전역 할당 방식의 MAC 주소 전체를 가리킨다.
- 하나의 장치에 여러 NIC가 있으면 여러 MAC 주소를 가질 수 있다.
- 가상 NIC와 Wi-Fi 임의 주소처럼 MAC 주소는 소프트웨어로 생성되거나 변경될 수 있다.
- MAC 주소는 로컬 링크에서 사용되며 라우터를 통과할 때 새 프레임의 주소로 바뀐다.

MAC 주소를 장치에 영구적으로 새겨진 절대적인 식별자로만 이해하기보다, 각 링크에서 네트워크 인터페이스와 프레임의 전달 대상을 구분하는 주소로 이해하는 것이 정확하다.
