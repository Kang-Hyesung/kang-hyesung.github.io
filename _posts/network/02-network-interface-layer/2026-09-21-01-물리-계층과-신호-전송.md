네트워크에서 주고받는 데이터는 논리적으로 `0`과 `1`의 비트열이지만, 비트 자체가 케이블이나 공기 중을 이동하는 것은 아니다. 송신 장치는 비트를 전송 매체에 맞는 물리 신호로 바꾸고, 수신 장치는 도착한 신호에서 다시 비트를 복원해야 한다.

이 변환과 전송을 담당하는 곳이 OSI 모델의 **물리 계층(Physical Layer)**이다. TCP/IP 모델에서는 물리 계층과 데이터 링크 계층의 기능을 합쳐 **네트워크 인터페이스 계층** 또는 네트워크 액세스 계층으로 설명한다.

## 네트워크 인터페이스 계층과 물리 계층

TCP/IP 모델의 네트워크 인터페이스 계층은 장치가 실제 네트워크 매체를 통해 데이터를 주고받는 가장 아래 영역이다. 이를 OSI 모델로 세분화하면 데이터 링크 계층과 물리 계층으로 나눌 수 있다.

| TCP/IP 모델 | OSI 모델 | 주요 역할 | 데이터 단위 |
| :--- | :--- | :--- | :--- |
| 네트워크 인터페이스 계층 | 데이터 링크 계층 | 프레임 구성, MAC 주소 기반 전달, 오류 검출 | 프레임 |
| 네트워크 인터페이스 계층 | 물리 계층 | 비트와 물리 신호의 변환, 매체를 통한 신호 전송 | 비트 |

두 계층은 밀접하게 동작한다. 데이터 링크 계층이 Ethernet 프레임을 구성하면 물리 계층은 그 프레임을 이루는 비트를 순서대로 신호로 바꿔 전송한다. 수신 측 물리 계층은 신호에서 비트를 복원하고, 데이터 링크 계층은 복원된 비트열을 프레임으로 해석한다.

## 물리 계층이 정의하는 것

물리 계층은 단순히 케이블만 다루는 계층이 아니다. 장치와 전송 매체가 같은 규칙으로 신호를 만들고 해석하도록 물리적인 통신 조건을 정의한다.

- 비트열을 전기·광·무선 신호로 표현하는 방법
- 신호의 전압, 광 파장, 주파수와 타이밍 같은 특성
- 전송 속도와 송수신 방향
- 케이블, 광섬유, 안테나 같은 전송 매체
- 커넥터 모양, 핀 배열, 최대 전송 거리
- 수신 신호에서 타이밍을 맞추고 비트를 복원하는 방법

물리 계층은 전달하려는 데이터가 HTTP인지 IP 패킷인지 해석하지 않는다. 목적지 IP 주소나 MAC 주소를 보고 전송 대상을 결정하지도 않는다. 상위 계층이 만든 비트열의 의미보다는 **신호를 어떻게 보내고 다시 비트로 복원할지**에 집중한다.

## 비트가 신호가 되어 전달되는 과정

PC A가 PC B로 Ethernet 프레임을 보낸다고 가정하면 물리 계층에서는 다음 흐름이 일어난다.

```mermaid
flowchart LR
  frameA["PC A<br/>프레임"]
  bitsA["송신 비트열"]
  txPhy["송신 PHY"]
  medium["전송 매체"]
  rxPhy["수신 PHY"]
  bitsB["수신 비트열"]
  frameB["PC B<br/>프레임"]

  frameA -->|"직렬화"| bitsA
  bitsA -->|"부호화·변조"| txPhy
  txPhy -->|"전기·광·무선 신호"| medium
  medium --> rxPhy
  rxPhy -->|"신호 해석"| bitsB
  bitsB -->|"프레임 복원"| frameB

  classDef dataLink fill:#14532d,stroke:#4ade80,stroke-width:2px,color:#f8fafc
  classDef bitStream fill:#713f12,stroke:#facc15,stroke-width:2px,color:#f8fafc
  classDef physical fill:#164e63,stroke:#22d3ee,stroke-width:2px,color:#f8fafc

  class frameA,frameB dataLink

```

1. 데이터 링크 계층이 만든 프레임이 전송할 비트열로 직렬화된다.
2. 송신 PHY가 비트열을 매체에 적합한 신호로 부호화하거나 변조한다.
3. 트랜시버가 신호를 구리선, 광섬유 또는 무선 공간으로 보낸다.
4. 수신 PHY가 도착한 신호를 측정하고 송신 측의 타이밍에 맞춰 값을 판별한다.
5. 복원한 비트열을 데이터 링크 계층에 전달하고 프레임으로 해석한다.

여기서 **PHY**는 Physical Layer의 줄임말로, 물리 계층의 송수신 기능을 구현한 회로나 장치를 가리킨다. 실제 네트워크 인터페이스 카드에는 데이터 링크 계층의 MAC 기능과 물리 계층의 PHY 기능이 함께 들어 있는 경우가 많다.

## 전송 매체에 따라 신호가 달라진다

입문 설명에서는 물리 계층이 비트를 전기 신호로 변환한다고 흔히 표현한다. 구리 케이블에는 맞는 설명이지만 모든 전송 매체가 전기 신호를 사용하는 것은 아니다.

| 전송 매체 | 사용하는 물리 신호 | 대표 사례 |
| :--- | :--- | :--- |
| 구리 케이블 | 전압과 전류의 변화 | UTP Ethernet 케이블 |
| 광섬유 | 빛의 세기·위상·파장 변화 | 광 Ethernet, 장거리 백본 |
| 무선 공간 | 전자기파의 진폭·주파수·위상 변화 | Wi-Fi, 이동통신 |

따라서 물리 계층의 역할은 비트를 무조건 전기 신호로 바꾸는 것이 아니라, **선택한 매체가 운반할 수 있는 신호로 표현하는 것**이라고 이해하는 편이 정확하다.

### 비트와 신호는 같은 것이 아니다

비트는 `0` 또는 `1`이라는 논리적 정보이고, 신호는 그 정보를 실제 매체에 실어 보내기 위한 물리량의 변화다. 단순한 그림에서는 높은 전압을 `1`, 낮은 전압을 `0`으로 표시하지만 실제 통신은 잡음과 대역폭을 고려해 더 복잡한 부호화와 변조 방식을 사용한다.

하나의 신호 상태인 **심볼(Symbol)**이 언제나 비트 하나만 표현하는 것도 아니다. 여러 단계의 진폭이나 위상을 사용하면 한 심볼이 여러 비트를 나타낼 수 있다. 그래서 다음 두 속도는 구분해야 한다.

- **비트율(Bit rate)**: 1초에 전달하는 비트 수, 단위는 `bit/s` 또는 `bps`
- **심볼률(Symbol rate)**: 1초에 전송하는 심볼 수, 단위는 `baud`

두 값이 같은 통신 방식도 있지만, 한 심볼이 여러 비트를 표현하면 비트율이 심볼률보다 커질 수 있다.

## 물리 계층과 관련된 장치

물리 계층 장치는 신호를 생성·전달·복원하거나 물리 연결을 연장한다.

| 장치와 구성 요소 | 역할 |
| :--- | :--- |
| 케이블·커넥터·안테나 | 신호가 이동할 물리 경로 제공 |
| 트랜시버·PHY | 비트와 매체 신호 사이를 변환 |
| 리피터(Repeater) | 약해지거나 왜곡된 신호를 복원하여 전송 거리 연장 |
| 더미 허브(Dummy Hub) | 한 포트에서 받은 신호를 나머지 포트로 반복 전송 |
| 모뎀(Modem) | 통신 회선에 맞게 신호를 변조하고 복조 |

### 더미 허브가 신호를 전달하는 방식

더미 허브는 여러 포트를 가진 리피터처럼 동작한다. 한 포트에서 신호를 받으면 목적지 MAC 주소를 해석하지 않고 다른 포트로 그대로 반복한다. 모든 장치가 같은 매체와 대역폭을 공유하므로 동시에 송신하면 충돌이 발생할 수 있고, 일반적으로 반이중 통신을 사용한다.

> 더미 허브가 모든 포트로 신호를 반복하는 동작과 Ethernet 브로드캐스트 프레임은 구분해야 한다. 허브는 프레임의 목적지 주소를 읽고 브로드캐스트로 바꾸는 것이 아니라, 물리 계층에서 들어온 신호를 단순히 다른 포트로 복제한다.
{: .prompt-info }

현대 LAN에서는 더미 허브보다 스위치를 사용한다. 스위치는 MAC 주소 테이블을 바탕으로 프레임을 전달하므로 주로 데이터 링크 계층 장비로 분류한다. 다만 스위치의 각 포트에도 케이블 신호를 처리하는 PHY가 있으므로 실제 장비 하나가 오직 한 계층의 기능만 가진다고 볼 수는 없다.

## 링크가 연결되었다는 것과 통신 가능하다는 것은 다르다

Ethernet 케이블을 연결했을 때 링크 표시등이 켜지거나 운영체제에 `연결됨`이 표시되면 양쪽 PHY가 신호를 감지하고 속도·통신 방식을 협상했다는 뜻이다. 이는 물리 계층 연결이 준비되었다는 중요한 단서지만 IP 통신까지 정상이라는 의미는 아니다.

물리 링크가 정상이어도 다음 문제로 통신하지 못할 수 있다.

- 스위치 포트의 VLAN 설정이 잘못됨
- DHCP에서 IP 주소를 받지 못함
- IP 주소, 서브넷 마스크, 기본 게이트웨이가 잘못됨
- 방화벽이나 라우팅 정책이 트래픽을 차단함
- DNS 조회에 실패함

장애를 확인할 때는 먼저 케이블, 링크 상태, 협상 속도 같은 물리 계층을 살펴보고 그다음 데이터 링크와 IP 설정을 확인하면 범위를 체계적으로 좁힐 수 있다.

## Windows에서 물리 링크 확인하기

현재 네트워크 어댑터의 연결 상태와 협상된 링크 속도는 PowerShell에서 확인할 수 있다.

```powershell
Get-NetAdapter | Format-Table Name, Status, LinkSpeed, MacAddress
```

특정 어댑터의 송수신 통계와 오류 카운터는 다음 명령으로 확인한다. 어댑터 이름은 환경에 맞게 바꿔야 한다.

```powershell
Get-NetAdapterStatistics -Name "Ethernet"
```

링크가 끊겨 있으면 `Status`가 `Disconnected`로 표시되거나 `ipconfig /all`에서 `Media disconnected`를 확인할 수 있다. 링크가 연결되어 있는데 통신이 되지 않는다면 DHCP, IP 주소, VLAN, 게이트웨이처럼 상위 계층 설정으로 점검 범위를 넓힌다.

> 링크 속도는 네트워크 인터페이스와 바로 연결된 장치 사이에서 협상한 물리 링크의 최대 속도다. 인터넷 다운로드 속도나 애플리케이션 처리량을 그대로 의미하지 않는다.
{: .prompt-tip }

## 정리

- TCP/IP의 네트워크 인터페이스 계층은 OSI의 데이터 링크 계층과 물리 계층에 대응한다.
- 물리 계층은 비트열을 전송 매체에 맞는 신호로 바꾸고, 수신 신호에서 비트를 복원한다.
- 구리선은 전기 신호, 광섬유는 빛, 무선은 전자기파를 사용하므로 모든 물리 전송이 전기 신호인 것은 아니다.
- 비트는 논리적 정보이고 신호와 심볼은 이를 물리적으로 표현하는 수단이다.
- PHY, 트랜시버, 리피터, 더미 허브, 케이블과 안테나가 물리 계층과 밀접하게 관련된다.
- 더미 허브는 MAC 주소를 해석하지 않고 입력 신호를 다른 포트로 반복한다.
- 실제 NIC와 스위치처럼 하나의 장비가 여러 계층의 기능을 함께 구현할 수 있다.
- 물리 링크가 연결되어도 DHCP, IP, VLAN, 라우팅 문제로 상위 계층 통신은 실패할 수 있다.

물리 계층을 이해하면 데이터가 단순한 `0`과 `1`에서 끝나는 것이 아니라, 실제 케이블과 공기를 통과하는 신호로 어떻게 바뀌고 다시 프레임으로 복원되는지 연결해서 볼 수 있다.
