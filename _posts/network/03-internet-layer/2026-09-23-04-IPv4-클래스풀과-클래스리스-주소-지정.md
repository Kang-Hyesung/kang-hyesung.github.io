`192.168.10.1`이라는 IPv4 주소만 보고 어디까지가 네트워크 부분인지 알 수 있을까? 과거의 **클래스풀(Classful) 주소 지정**에서는 주소의 첫 비트 패턴에 따라 A·B·C 클래스를 정하고 기본 네트워크 크기를 유추했다. 현재의 **클래스리스(Classless) 주소 지정**에서는 `192.168.10.1/24`처럼 프리픽스 길이를 함께 표시해 경계를 정한다.

두 방식의 차이를 이해하면 `/24`가 왜 주소 옆에 붙는지, 같은 IP 주소라도 프리픽스에 따라 소속 네트워크가 어떻게 달라지는지 알 수 있다.

## IP 주소만으로 네트워크 범위를 알 수 있을까

IPv4 주소는 32비트이며, 점으로 구분한 네 숫자는 각각 8비트다. 예를 들어 `192.168.10.1`은 다음과 같이 표현된다.

```text
192      .168      .10       .1
11000000 .10101000 .00001010 .00000001
```

이 32비트 중 앞부분은 **네트워크 프리픽스**, 나머지는 그 네트워크 안의 **호스트 부분**이다. 경계가 어디인지 알아야 네트워크 주소와 주소 범위를 계산할 수 있다. 주소 뒤에 붙는 `/24`는 앞의 24비트가 네트워크 부분이라는 뜻이고, `255.255.255.0` 서브넷 마스크와 같은 경계를 나타낸다.

> IP 주소의 네트워크 부분은 주소 숫자 자체에 새겨진 고정 속성이 아니다. 현재 사용하는 프리픽스 길이 또는 서브넷 마스크를 함께 봐야 한다.
{: .prompt-info }

## 클래스풀 주소 지정: 클래스별 기본 크기

초기 IPv4 주소 체계는 첫 옥텟의 범위로 주소를 분류했다. A·B·C 클래스의 **기본 네트워크 길이**는 각각 `/8`, `/16`, `/24`다.

| 클래스 | 첫 옥텟 범위 | 기본 프리픽스 | 기본 서브넷 마스크 | 용도 |
| :---: | :--- | :---: | :--- | :--- |
| A | `1`~`126` | `/8` | `255.0.0.0` | 호스트 주소 지정 |
| B | `128`~`191` | `/16` | `255.255.0.0` | 호스트 주소 지정 |
| C | `192`~`223` | `/24` | `255.255.255.0` | 호스트 주소 지정 |
| D | `224`~`239` | 해당 없음 | 해당 없음 | 멀티캐스트 |
| E | `240`~`255` | 해당 없음 | 해당 없음 | 예약·실험용 범위 |

이 표의 범위는 첫 옥텟만 보여준다. 예를 들어 C 클래스의 첫 옥텟은 `192`부터 `223`까지다. `192.168.0.0`부터만 C 클래스인 것은 아니다. 또한 `0/8`은 특수 용도로, `127/8`은 루프백으로 예약되어 있어 일반적인 A 클래스 호스트 범위에서 제외했다. D·E는 A·B·C처럼 일반 호스트 네트워크를 할당하는 클래스가 아니다. E 범위 끝의 `255.255.255.255`는 제한된 브로드캐스트 주소로 사용된다.

`192.168.10.1`은 첫 옥텟이 `192`이므로 과거 클래스 기준으로 C에 속한다. 클래스의 **기본 경계**를 적용하면 앞의 24비트가 네트워크 부분이고 네트워크 주소는 `192.168.10.0/24`다.

```text
192.168.10.1    → C 클래스의 기본 길이 /24
192.168.10.0/24 → 기본 네트워크
```

클래스는 주소의 첫 비트로 정해지지만, 실제 인터페이스에 설정된 서브넷 마스크까지 첫 비트만으로 확정할 수 있는 것은 아니다. 클래스풀 환경에서도 기본 네트워크를 더 작은 서브넷으로 나누어 사용했다. 다만 클래스 경계를 전제로 한 주소 할당과 라우팅 방식은 다양한 규모의 네트워크를 유연하게 표현하는 데 한계가 있었다.

## 클래스리스 주소 지정: 필요한 크기를 프리픽스로 표현

클래스리스 주소 지정에서는 A·B·C의 기본 길이에 묶이지 않고 네트워크 프리픽스 길이를 명시한다. 이 방식을 사용하는 대표적인 표기가 **CIDR(Classless Inter-Domain Routing)**의 `/숫자` 형식이다.

같은 IP 주소라도 프리픽스를 다르게 주면 소속 네트워크가 달라진다.

| 인터페이스 표기 | 서브넷 마스크 | 소속 네트워크 | 전체 주소 범위 |
| :--- | :--- | :--- | :--- |
| `192.168.10.1/20` | `255.255.240.0` | `192.168.0.0/20` | `192.168.0.0`~`192.168.15.255` |
| `192.168.10.1/24` | `255.255.255.0` | `192.168.10.0/24` | `192.168.10.0`~`192.168.10.255` |
| `192.168.10.1/28` | `255.255.255.240` | `192.168.10.0/28` | `192.168.10.0`~`192.168.10.15` |

`/20`의 마스크 마지막 두 옥텟은 `11110000.00000000`이다. 따라서 셋째 옥텟의 앞 4비트만 네트워크 부분이다. `10`이 속한 16개 단위 구간은 `0`~`15`이므로 `192.168.10.1/20`의 네트워크 주소는 `192.168.0.0/20`이 된다. `/28`에서는 마지막 옥텟의 앞 4비트까지 네트워크 부분이며, 호스트 범위가 16개 주소 단위로 나뉜다.

### 주소를 필요한 만큼 나누는 예

호스트 50개가 필요한 네트워크를 생각해 보자. C 클래스의 기본 `/24` 전체를 할당하면 주소 256개 중 일반적으로 254개를 호스트에 사용할 수 있으므로 필요량에 비해 큰 범위를 잡게 된다. `/26`으로 나누면 6비트가 호스트 부분이 되어 총 `2^6 = 64개`의 주소를 담는다. 일반적인 서브넷에서 네트워크 주소와 브로드캐스트 주소를 제외하면 **62개**를 호스트에 할당할 수 있다.

```text
192.168.10.0/26
네트워크 주소:     192.168.10.0
호스트에 할당:    192.168.10.1 ~ 192.168.10.62
브로드캐스트 주소: 192.168.10.63
```

필요한 규모에 맞춰 프리픽스를 정하면 주소 낭비를 줄일 수 있다. 또한 여러 연속된 네트워크를 하나의 큰 프리픽스로 묶어 라우팅 정보를 간결하게 표현할 수도 있다. 이때 프리픽스가 커버하는 주소 범위가 실제로 연속되고 경계가 맞아야 한다.

> `192.168.10.1`이 C 클래스 범위에 속한다는 말은 역사적인 주소 분류다. 오늘날 실제 네트워크 범위를 판단할 때는 주소와 함께 설정된 `/20`, `/24`, `/28` 같은 프리픽스를 확인한다.
{: .prompt-warning }

## 정리

- 클래스풀 주소 지정은 A·B·C 클래스에 기본 네트워크 길이 `/8`, `/16`, `/24`를 부여했다.
- D 클래스는 멀티캐스트, E 클래스는 예약·실험용 범위로 일반 호스트 주소 할당과 구분한다.
- 클래스리스 주소 지정은 프리픽스 길이를 명시하므로 같은 IPv4 주소도 서로 다른 크기의 네트워크에 속할 수 있다.
- CIDR 표기 `192.168.10.1/24`에서 `/24`는 앞의 24비트가 네트워크 부분이라는 뜻이다.
- 프리픽스 길이를 조절하면 필요한 크기의 서브넷을 만들고, 연속된 경로를 요약할 수 있다.

라우터가 목적지 IP와 라우팅 테이블을 비교할 때도 이 프리픽스가 기준이 된다. 주소의 첫 옥텟만 보고 네트워크 범위를 추측하는 대신, 주소와 프리픽스를 함께 읽어야 한다.
