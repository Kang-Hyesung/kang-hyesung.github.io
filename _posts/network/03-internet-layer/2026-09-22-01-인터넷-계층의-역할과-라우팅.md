같은 LAN 안에서는 Ethernet 프레임과 MAC 주소를 이용해 인접 장치로 데이터를 전달할 수 있다. 하지만 목적지가 다른 네트워크에 있다면 로컬 링크를 넘어 여러 네트워크를 차례로 통과해야 한다.

TCP/IP 모델의 **인터넷 계층(Internet Layer)**은 IP 주소로 출발지와 목적지를 식별하고, 라우터를 거쳐 패킷을 다음 네트워크로 전달한다. OSI 모델의 네트워크 계층과 대체로 대응하며, 서로 독립된 네트워크를 하나의 인터넷으로 연결하는 역할을 한다.

## 네트워크 인터페이스 계층과 무엇이 다를까

네트워크 인터페이스 계층과 인터넷 계층은 모두 데이터를 전달하지만 다루는 범위가 다르다.

| 구분 | 네트워크 인터페이스 계층 | 인터넷 계층 |
| :--- | :--- | :--- |
| 전달 범위 | 현재 링크의 인접 장치까지 | 서로 다른 네트워크를 넘어 목적지까지 |
| 대표 주소 | MAC 주소 | IP 주소 |
| 데이터 단위 | 프레임 | 패킷 |
| 대표 장비 | 스위치, NIC | 라우터, 계층 3 스위치 |
| 주요 판단 | 어느 포트로 프레임을 보낼지 | 어느 다음 홉과 인터페이스로 패킷을 보낼지 |

네트워크 인터페이스 계층은 현재 구간에서 프레임을 전달하고, 인터넷 계층은 여러 구간을 이어 패킷이 목적지 네트워크까지 이동할 방향을 결정한다. 두 계층은 경쟁하는 것이 아니라 홉마다 함께 동작한다.

## 인터넷 계층의 핵심 역할

인터넷 계층은 다음 기능을 중심으로 동작한다.

- **논리 주소 지정**: IP 주소로 출발지와 목적지 인터페이스를 식별한다.
- **패킷화**: 전송 계층에서 받은 데이터를 IP 헤더로 캡슐화해 패킷을 만든다.
- **네트워크 간 전달**: 라우터를 통해 한 네트워크에서 다른 네트워크로 패킷을 넘긴다.
- **경로 선택**: 라우팅 테이블을 조회해 목적지로 향하는 다음 홉과 출력 인터페이스를 결정한다.
- **수명 제한**: TTL 또는 Hop Limit으로 패킷이 라우팅 루프에서 무한히 순환하지 않도록 한다.
- **상태·오류 전달**: ICMP로 도달 불가, 시간 초과와 진단 정보를 전달한다.

IP는 패킷을 목적지까지 보내려고 시도하지만 전달 성공, 중복 방지, 순서와 재전송을 보장하지 않는 **비연결형·최선형(Best Effort)** 프로토콜이다. 필요한 신뢰성은 TCP나 애플리케이션 같은 상위 계층에서 보완한다.

> IP 헤더에 있는 식별자와 단편화 관련 필드는 패킷의 전체 전송 순서를 보장하기 위한 정보가 아니다. 서로 다른 경로를 지난 IP 패킷은 순서가 바뀌어 도착할 수 있다.
{: .prompt-warning }

## IP 패킷과 IP 헤더

IP 패킷은 IP 헤더와 페이로드로 구성된다. 페이로드에는 일반적으로 TCP 세그먼트나 UDP 데이터그램 같은 전송 계층 데이터가 들어간다.

| IP 헤더의 주요 정보 | 역할 |
| :--- | :--- |
| 출발지 IP 주소 | 패킷을 보낸 인터페이스 식별 |
| 목적지 IP 주소 | 최종 수신 인터페이스 식별 |
| 전체 길이·페이로드 길이 | 패킷의 크기 표현 |
| TTL·Hop Limit | 통과할 수 있는 홉 수 제한 |
| 상위 프로토콜 식별자 | TCP, UDP, ICMP 등 다음 처리 대상 구분 |
| 단편화 관련 정보 | IPv4 단편의 식별과 재조립에 사용 |

IPv4와 IPv6는 헤더 구조가 다르다. IPv4에는 헤더 체크섬과 헤더 내 단편화 필드가 있지만 IPv6 기본 헤더에는 헤더 체크섬이 없고 단편화 정보는 확장 헤더로 분리된다. 세부 필드의 차이는 각 프로토콜을 다룰 때 살펴보는 편이 좋다.

## IP 주소와 네트워크 주소

IP 주소는 네트워크에 연결된 인터페이스를 논리적으로 식별한다. IPv4 주소 `192.168.10.25/24`를 예로 들면 `/24`는 앞의 24비트가 네트워크를 나타낸다는 뜻이다.

```text
호스트 IP 주소: 192.168.10.25/24
네트워크 주소: 192.168.10.0/24
호스트 부분:   25
```

라우터는 목적지 IP 주소 전체를 장치 목록처럼 검색하지 않는다. 목적지 주소가 어느 **네트워크 프리픽스**에 포함되는지 라우팅 테이블과 비교해 전달 방향을 결정한다. 서브넷 마스크와 CIDR 표기는 IP 주소에서 네트워크 부분과 호스트 부분의 경계를 나타낸다.

네트워크 주소는 특정 호스트 하나의 주소와 구분해야 한다. IPv4에서 `192.168.10.0/24`는 해당 서브넷 자체를 나타내는 프리픽스이고, `192.168.10.25`는 그 서브넷에 속한 인터페이스 주소의 예다.

## 라우터는 홉마다 프레임을 바꾼다

라우터는 서로 다른 네트워크를 연결하고 IP 패킷을 다음 홉으로 전달한다. 패킷이 라우터를 통과할 때 링크 계층 프레임은 구간마다 새로 만들어진다.

```mermaid
flowchart LR
  hostA["호스트 A"] -->|"링크 1<br/>프레임"| routerA["라우터 A"]
  routerA -->|"링크 2<br/>새 프레임"| routerB["라우터 B"]
  routerB -->|"링크 3<br/>새 프레임"| hostB["호스트 B"]

  classDef host fill:#14532d,stroke:#4ade80,stroke-width:2px,color:#f8fafc
  classDef router fill:#164e63,stroke:#22d3ee,stroke-width:3px,color:#f8fafc

  class hostA,hostB host
  class routerA,routerB router
```

1. 호스트 A는 목적지가 같은 네트워크에 없음을 확인하고 패킷을 기본 게이트웨이로 보낸다.
2. 라우터 A는 수신 프레임을 제거하고 IP 목적지와 라우팅 테이블을 확인한다.
3. TTL을 감소시키고 다음 링크에 맞는 새 프레임으로 패킷을 캡슐화한다.
4. 각 라우터가 같은 작업을 반복하고 마지막 라우터가 호스트 B가 있는 링크로 전달한다.

일반적인 통신에서는 출발지와 목적지 IP 주소가 종단 간 유지되지만 각 구간의 MAC 주소는 달라진다. NAT가 동작하면 경계 장비에서 IP 주소나 포트가 변환될 수 있으며, 라우터를 지날 때마다 TTL 또는 Hop Limit도 감소한다.

## 라우팅과 포워딩은 구분해야 한다

두 용어를 넓은 의미에서 함께 사용하기도 하지만 역할을 구분하면 라우터의 동작을 이해하기 쉽다.

- **라우팅(Routing)**: 도달 가능한 네트워크와 경로 정보를 학습하고 라우팅 테이블을 구성하는 과정
- **포워딩(Forwarding)**: 실제 패킷의 목적지 주소를 테이블과 비교해 다음 홉 또는 출력 인터페이스로 보내는 과정

라우터는 목적지 IP 주소와 가장 길게 일치하는 네트워크 프리픽스를 우선하는 **최장 프리픽스 일치(Longest Prefix Match)**로 경로를 찾는다. 같은 목적지에 여러 후보가 있다면 경로 출처, 메트릭과 정책 등을 비교해 사용할 경로를 선택한다.

따라서 라우팅에서 말하는 최적 경로는 언제나 물리적으로 가장 짧거나 지연 시간이 가장 낮은 경로를 뜻하지 않는다. 관리자가 정한 비용과 정책에 따라 선택된 가장 적합한 경로다.

목적지와 일치하는 구체적인 경로가 없을 때 사용할 수 있도록 **기본 경로(Default Route)**를 설정할 수 있다. 가정용 PC가 인터넷 목적지로 패킷을 보낼 때 공유기를 기본 게이트웨이로 사용하는 것이 대표적인 예다.

## 라우팅 정보는 어떻게 만들어질까

라우팅 테이블의 정보는 여러 방식으로 만들어진다.

| 경로 종류 | 만들어지는 방식 | 일반적인 용도 |
| :--- | :--- | :--- |
| 직접 연결 경로 | 라우터 인터페이스에 네트워크가 연결되면 생성 | 바로 연결된 네트워크 |
| 정적 경로 | 관리자가 목적지와 다음 홉을 직접 설정 | 단순하거나 고정된 경로 |
| 동적 경로 | 라우팅 프로토콜로 다른 라우터와 정보 교환 | 규모가 크고 변화하는 네트워크 |

대표적인 라우팅 프로토콜에는 RIP, OSPF와 BGP가 있다.

- **RIP**: 홉 수를 기준으로 경로를 선택하는 단순한 내부 라우팅 프로토콜
- **OSPF**: 링크 상태와 비용을 바탕으로 한 조직 내부의 라우팅 프로토콜
- **BGP**: 인터넷의 자율 시스템 사이에서 경로와 정책 정보를 교환하는 프로토콜

라우팅 프로토콜이 사용자 데이터를 직접 운반하는 것은 아니다. 라우터끼리 경로 정보를 교환해 라우팅 테이블을 구성하도록 돕고, 실제 사용자 패킷은 그 결과를 이용해 포워딩된다.

## NAT는 IP 라우팅과 관련되지만 별도의 기능이다

사설 IPv4 주소를 사용하는 장치가 인터넷에 접속할 때 가정용 공유기는 흔히 NAT(Network Address Translation)를 수행한다. 내부의 사설 주소와 포트를 공유기의 공인 주소와 대응시켜 응답 패킷이 올바른 내부 장치로 돌아가게 한다.

NAT는 이름에 `Translation`이 들어가는 주소 변환 메커니즘이며, IP처럼 종단 장치가 반드시 사용하는 하나의 통신 프로토콜이라고 보기는 어렵다. 라우터가 모든 패킷에 반드시 NAT를 적용하는 것도 아니다. 공인 주소끼리 통신하거나 IPv6를 종단 간 라우팅하는 환경에서는 주소 변환 없이 라우팅할 수 있다.

## Windows에서 경로 확인하기

현재 IP 주소, 서브넷 마스크와 기본 게이트웨이는 다음 명령으로 확인한다.

```powershell
ipconfig
```

Windows가 사용하는 라우팅 테이블은 다음 명령으로 확인할 수 있다.

```powershell
route print
```

목적지까지 거치는 라우터 홉은 `tracert`로 확인한다.

```powershell
tracert example.com
```

각 행은 패킷의 TTL을 점차 늘려가며 확인한 경로상의 홉을 나타낸다. 일부 라우터가 진단 메시지에 응답하지 않거나 방화벽이 차단하면 `*`가 표시될 수 있으므로, 별표가 있다고 해서 그 지점에서 실제 데이터 전달도 반드시 실패한 것은 아니다.

## 정리

- 인터넷 계층은 IP 주소를 이용해 서로 다른 네트워크 사이로 패킷을 전달한다.
- IP는 비연결형·최선형 프로토콜이며 전달 성공, 순서와 재전송을 보장하지 않는다.
- IP 헤더에는 출발지·목적지 주소, 패킷 길이, 수명과 상위 프로토콜 정보 등이 들어간다.
- 라우터는 홉마다 링크 계층 프레임을 교체하고 라우팅 테이블을 이용해 다음 경로를 선택한다.
- 라우팅은 경로 정보를 구성하는 과정이고 포워딩은 실제 패킷을 다음 홉으로 보내는 과정이다.
- 라우터는 최장 프리픽스 일치와 메트릭·정책을 바탕으로 경로를 선택한다.
- RIP·OSPF·BGP 같은 라우팅 프로토콜은 라우터가 경로 정보를 교환하도록 돕는다.
- NAT는 사설 주소와 공인 주소 사이의 통신에 자주 사용되지만 IP 자체와 같은 필수 통신 프로토콜은 아니다.

인터넷 계층의 전체 흐름을 이해하면 이후 IP 주소와 서브넷, IP 헤더, ICMP, NAT, 라우터와 라우팅 프로토콜을 배울 때 각 개념이 네트워크 간 통신에서 어떤 역할을 맡는지 연결해서 볼 수 있다.
