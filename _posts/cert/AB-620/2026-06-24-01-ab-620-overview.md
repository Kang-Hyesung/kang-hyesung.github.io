## 학습 목표

이 단계의 목표는 AB-620 시험 전체를 한눈에 보는 것이다.

아직 깊게 외우지 않아도 된다.  
대신 시험에서 반복해서 등장하는 큰 덩어리 10개를 먼저 구분할 수 있어야 한다.

## AB-620을 한 문장으로 정리

AB-620은 **Microsoft Copilot Studio로 엔터프라이즈 AI agent를 설계하고, 외부 시스템과 통합하고, 테스트/운영/배포할 수 있는지**를 묻는 시험이다.

핵심은 다음 세 가지다.

1. Agent를 어떻게 설계할 것인가?
2. Agent가 어떤 지식과 도구를 사용하게 할 것인가?
3. 만든 agent를 어떻게 안전하게 운영할 것인가?

## 시험의 공식 영역

| 영역 | 비중 | 쉬운 설명 |
| --- | ---: | --- |
| Plan and configure agent solutions | 30-35% | agent 설계, topic, flow, 보안, 채널 |
| Integrate and extend agents in Copilot Studio | 40-45% | connector, API, MCP, Foundry, Fabric, A2A |
| Test and manage agents | 20-25% | 평가, 테스트, ALM, pipeline, environment variable |

가장 중요한 영역은 **Integrate and extend agents**다.  
즉, 시험에서는 "어떤 상황에 어떤 통합 방식을 써야 하는가?"가 매우 자주 나온다.

## 시험 핵심 주제 10개

## 1. Agent 설계

Agent는 사용자의 자연어 요청을 받아 답변하거나 작업을 실행하는 AI 애플리케이션이다.

시험에서는 다음을 묻는다.

- 내부 사용자용인지 외부 고객용인지
- 어떤 채널에 배포할지
- 어떤 인증을 사용할지
- 어떤 데이터를 접근하게 할지
- 보안과 거버넌스를 어떻게 적용할지

## 2. Instructions와 Orchestration

Instructions는 agent의 역할과 행동 기준이다.

Orchestration은 agent가 사용자의 요청을 보고 어떤 topic, tool, knowledge source, 다른 agent를 사용할지 결정하는 과정이다.

시험에서는 다음을 묻는다.

- 자동으로 적절한 tool을 고르게 할 것인가?
- 정해진 topic 흐름을 따르게 할 것인가?
- tool과 topic 설명을 어떻게 작성해야 하는가?

## 3. Topics

Topic은 정해진 대화 흐름이다.

예를 들면 다음과 같다.

- 휴가 신청
- 주문 상태 조회
- 티켓 생성
- 승인 요청

시험에서는 "사용자에게 값을 순서대로 받고, 조건에 따라 분기하고, tool을 호출해야 한다"는 식으로 나온다.

## 4. Knowledge와 Generative Answers

Knowledge source는 agent가 답변할 때 참고하는 정보 원본이다.

Generative answers는 knowledge source를 검색해서 답변을 생성하는 기능이다.

시험에서는 다음 표현과 연결된다.

- 문서 기반 답변
- SharePoint 기반 Q&A
- citation
- grounded answer
- RAG

## 5. Tools

Tool은 agent가 실제 작업을 하게 만드는 기능이다.

예를 들면 다음과 같다.

- API 호출
- 주문 조회
- 티켓 생성
- connector 실행
- agent flow 실행
- MCP tool 사용

시험에서는 "answer"보다 "perform", "retrieve", "create", "update", "call" 같은 표현이 나오면 tool을 생각해야 한다.

## 6. Connectors와 REST API

Connector는 Microsoft 또는 외부 서비스와 연결하는 표준 방식이다.

REST API tool은 OpenAPI specification을 이용해 API endpoint를 agent tool로 추가하는 방식이다.

시험에서는 다음을 구분해야 한다.

- 이미 connector가 있으면 connector
- 조직 내부 API를 재사용하려면 custom connector
- 특정 REST endpoint를 직접 연결하려면 REST API tool

## 7. MCP와 Computer Use

MCP는 Model Context Protocol이다.  
외부 MCP server가 제공하는 tools/resources를 agent가 사용할 수 있게 한다.

Computer use는 API나 connector가 없는 GUI 기반 시스템을 agent가 화면 조작으로 자동화하는 방식이다.

시험에서는 다음을 구분한다.

- MCP server가 있으면 MCP
- API 없이 웹/데스크톱 화면만 있으면 Computer use

## 8. Multi-agent, Foundry, Fabric, A2A

Multi-agent solution은 여러 agent가 역할을 나누어 협업하는 구조다.

대표 유형:

- 기존 Copilot Studio agent 연결
- Microsoft Foundry agent 연결
- Fabric data agent 연결
- A2A protocol로 외부 agent 연결

시험에서는 "다른 agent에게 task를 위임한다"는 표현이 나오면 이 영역을 떠올린다.

## 9. Evaluation과 Monitoring

Evaluation은 agent 답변 품질을 반복적으로 검증하는 것이다.

Monitoring은 운영 중 agent의 상태와 오류를 관찰하는 것이다.

구분:

| 목적 | 기능 |
| --- | --- |
| 답변 품질 평가 | Test set, Evaluation method |
| 운영 로그/오류/성능 추적 | Application Insights |
| 대화 흐름 수동 확인 | Test chat, Activity map |

## 10. ALM

ALM은 Application Lifecycle Management다.

Agent를 개발, 테스트, 운영 환경으로 안전하게 이동하고 관리하는 체계다.

중요 개념:

- Solution
- Environment
- Environment variable
- Connection reference
- Managed solution
- Power Platform Pipelines

시험에서는 "dev/test/prod", "환경별 설정값", "배포 자동화" 같은 표현으로 나온다.

## 가장 중요한 1차 구분

시험 문제를 보면 먼저 아래를 구분한다.

| 문제 요구 | 먼저 떠올릴 개념 |
| --- | --- |
| 정해진 대화 흐름 | Topic |
| 문서 기반 답변 | Knowledge source / Generative answers |
| 외부 시스템 작업 실행 | Tool |
| 여러 단계 업무 자동화 | Agent flow |
| 외부 API 직접 호출 | REST API tool |
| 조직 API 재사용 | Custom connector |
| 외부 tool server 연결 | MCP |
| 다른 agent에게 위임 | A2A / Connected agent |
| 운영 모니터링 | Application Insights |
| 환경 간 배포 | Solution / Pipeline |

## 1단계 복습 질문

**Q1. AB-620에서 가장 비중이 큰 영역은 무엇인가?**

<details>
<summary>정답 확인</summary>
<div>
가장 비중이 큰 영역은 **Integrate and extend agents in Copilot Studio**다. 시험 비중은 40-45%이며 connector, API, MCP, Foundry, Fabric, A2A 같은 통합과 확장 방식을 주로 다룬다.
</div>
</details>

**Q2. Topic과 Tool의 가장 큰 차이는 무엇인가?**

<details>
<summary>정답 확인</summary>
<div>
Topic은 사용자를 정해진 대화 흐름으로 안내하는 구성이고, Tool은 외부 시스템에서 데이터를 가져오거나 실제 작업을 실행하는 구성이다.
</div>
</details>

**Q3. Knowledge source와 Tool의 차이는 무엇인가?**

<details>
<summary>정답 확인</summary>
<div>
Knowledge source는 문서나 데이터 원본을 검색해 답변을 생성할 때 사용한다. Tool은 주문 조회, 티켓 생성, API 호출처럼 시스템에 작업을 수행시킬 때 사용한다.
</div>
</details>

**Q4. MCP와 A2A는 각각 무엇과 연결되는가?**

<details>
<summary>정답 확인</summary>
<div>
MCP는 외부 tool/resource server와 연결한다. A2A는 다른 agent와 연결해 task를 위임할 때 사용한다.
</div>
</details>

**Q5. ALM에서 environment variable은 왜 필요한가?**

<details>
<summary>정답 확인</summary>
<div>
개발, 테스트, 운영 환경마다 달라지는 API URL, 사이트 주소, endpoint 같은 설정값을 코드나 agent 자체에 하드코딩하지 않기 위해 필요하다.
</div>
</details>

## 다음 단계로 가기 전 기준

아래 문장을 설명할 수 있으면 2단계로 넘어가면 된다.

> AB-620은 Copilot Studio agent가 사용자의 요청을 처리하기 위해 topic, knowledge, tool, 다른 agent를 적절히 선택하고, 이를 보안과 ALM 체계 안에서 운영할 수 있는지를 평가하는 시험이다.
